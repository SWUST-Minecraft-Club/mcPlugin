# 小镇经营、迁移与资源集成经验

## 钱包扣款与本地业务不能靠一个回调保证恢复

- **现象**：请求超时无法区分“未扣款”和“已扣款但回复丢失”，直接生成新业务号重试会重复扣费；只记录最终结果会留下崩溃窗口。
- **根因**：Wallet、Town 数据和世界方块不共享事务。
- **规避/解决**：操作先持久登记固定业务号；扣款、业务应用、收款、退款分别推进状态。明确拒绝才终止，网络不确定保留业务号重试。本地应用保存已处理 ID；房产、商品与报价版本在实际提交时重验。
- **来源**：2026-10-26，Town Beta_0_6_0；`./Minecraft-26_3-plugin/Town/src/main/java/com/example/town/economy/DurablePayments.java`、对应测试。

## 收件箱交付应对背包保存与邮件扣减之间的中断

- **现象**：先减邮件后发物品可能丢失；先发后减可能在重启后重复领取。
- **根因**：玩家背包由服务端保存，邮件由插件保存，不能一起原子提交。
- **规避/解决**：持久化交付前后背包镜像及意图，冻结相关操作；玩家线程应用后保存背包，再完成邮件记录。恢复时比较 before/after；无法匹配的冲突保留并供管理员核对，不能猜测。自己的补发核心、测绘工具也应遵守冻结状态。
- **来源**：2026-10-26，Town；`./Minecraft-26_3-plugin/Town/src/main/java/com/example/town/market/`，双客户端重启收件箱联调。

## 重叠迁移必须按源区与目标区并集计算最终方块

- **现象**：逐块“清空源方块、复制到目标”会覆盖尚未读取的源区；只快照非重叠部分不能撤回。
- **根因**：源区和目标区可能相交，旋转后坐标映射也改变。
- **规避/解决**：施工前完整快照并集，所有写入从不可变快照计算；完成前持续施工锁，按工程阶段重放。容器/告示牌通过 Bukkit Structure 保存单块 NBT。验收独立提交地块、商铺和政厅坐标，并使用幂等标记。
- **来源**：2026-10-26，Town；`./Minecraft-26_3-plugin/Town/src/main/java/com/example/town/relocation/`，真实 CE 90° 重叠迁移及撤回。

## CraftEngine 的显示实体不等于家具持久身份

- **现象**：服务器重启后客户端看到的 item_display UUID 改变，容易误判家具恢复失败。
- **根因**：CraftEngine 可以重建视觉实体；实际 loaded furniture 的 baseEntity 是另一个实体。
- **规避/解决**：通过 CE API 解析所属家具、保存核心实体 UUID 与 ID/变体，并使用 moveTo 移动原家具；验证时核对 canonical 身份、碰撞范围和位置。CE 自定义方块保存 ID 与属性，恢复用 ImmutableBlockState 的公开 place API，投影也解析旋转后的真实外观。
- **来源**：2026-10-26，CraftEngine 26.9.2 本地源码与联调；`./Minecraft-26_3-plugin/Town/src/main/java/com/example/town/hook/CraftEngineHook.java`。

## 清除旧世界投影时应防止覆盖下一份预览

- **现象**：连续移动目标时，旧预览异步恢复真实方块，可能覆盖新投影的相同坐标。
- **根因**：跨区块读取与玩家发包的完成顺序不保证等同于草案创建顺序。
- **规避/解决**：发回真实方块前检查当前预览集合仍未使用该坐标；草案扫描完成后比较令牌/对象身份，只发布当前结果。所有世界读写进入对应 Folia 区域，给玩家发送投影进入玩家线程。
- **来源**：2026-10-26，Town 规划预览；`./Minecraft-26_3-plugin/Town/src/main/java/com/example/town/relocation/RelocationService.java`。
