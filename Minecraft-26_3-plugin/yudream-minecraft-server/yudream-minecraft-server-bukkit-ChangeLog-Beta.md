# yudream-minecraft-server ChangeLog（测试版）

版本命名与产物见 `./docs/dev/版本与产物规范.md`。
格式：`[新版本] 时间` 或 `[上一版本 -> 新版本] 时间`，下面列本次改动（新增 / 修复 / 调整）。

---

[1.6.2 -> Beta_1_7_0] 2026.10.19 13:50:00
1.新增：本地在线时长统计（`local-playtime`）—— 口径与 YuDream Admin 后端逐条对齐
   （在线时长 = 已结算区间 + 当前未结算区间，AFK 时长单独累计、不从在线时长里扣；
   重复上线不重置起点、重复下线不重复结算），后端不可用或还没配好时也照常记账；
   数据落在插件数据目录的 `playtime.yml`
2.新增：待发上报落盘（`durable-queue`）—— 进服 / 退服 / AFK 起止先写 `pending-reports.jsonl`，
   后端恢复后按原始时间戳按序补发，进程重启不丢；聊天 / 死亡 / 成就这类消息型事件仍保持尽力而为语义
3.新增：`/yudreammc playtime [玩家]` 子命令，就地核对本地在线时长 / AFK 时长 / 待发条数
4.调整：AFK 计时不再依赖后端是否可用（原来 `canReport()` 为 false 时根本不计时），
   现在后端挂着也能统计本地在线与挂机时长；上报路径的门禁逻辑保持不变
5.调整：源码从官方 1.6.2 产物的反编译基线纳入本仓，改为 Gradle 工程构建
   （编译目标 spigot-api 1.13.2、Java 8 字节码；产物沿用 `yudream-minecraft-server-bukkit-<版本>.jar` 命名）；
   反编译失真导致的 3 处无法编译做了最小修正，行为不变

[Beta_1_7_0 -> Beta_1_8_0] 2026.10.19 14:40:00
1.新增：本地台账定期与后端对齐（`local-playtime.sync-from-backend`，默认每 300 秒一次）——
   本地台账只从本插件开始记账那一刻算起，后端可能有更早的历史，不对齐两边会差一个历史量。
   已结算累计取两边较大值；当前区间只认"玩家此刻确实在线"的那一侧并取更早的起点，
   所以只会补齐历史，不会把离线时间算成在线。
2.修复了玩家活动列表接口的路径：后端列表挂在**管理端** `/admin/servers/{id}/players` 下
   （原路径 `/servers/{id}/players` 在现版本后端不存在，`/yudreammc status` 的远端统计一直拿不到数据）；
   需要 API key 带 `plugin:minecraft-server:manage` 权限，旧后端仍会回退到原路径
3.说明：下游（代理）模式不加对齐 —— 那种部署下凭证在代理侧，本机拉不到列表，本地数字仅代表本机观测

[Beta_1_8_0 -> Beta_1_8_1] 2026.10.19 15:20:00
1.修复了"本地时长与后端对不上"：平台给插件的响应默认带一层信封（`PluginHttpResponse.ok` 的 `wrapped=true`），
   玩家列表实际在 `{"code":..,"message":..,"data":{"records":[...],"total":N}}` 的 `data` 里，
   而解析器原来只在顶层找 `records`，于是每次对齐都被判定成"响应里没有 records 数组"而静默跳过
   （表现为本地数字永远补不上后端的历史）。现在 `data` 与顶层两种形状都认。
2.新增：`/yudreammc syncplaytime` —— 立即对齐一次，成功条数与失败原因（含 HTTP 状态码）直接回在聊天框里；
   `/yudreammc status` 也增加插件版本、本地统计开关、对齐间隔与最近一次对齐结果，
   排查不必再翻服务端日志（玩家列表在管理端路径下，需要 API key 带 `plugin:minecraft-server:manage` 权限）。

[Beta_1_8_1 -> Beta_1_8_2] 2026.10.19 16:30:00
1.修复了"拿到记录却没对齐"：平台把长整型序列化成**字符串**（信封里的 timestamp 就是字符串），
   而原来的字段解析只认数字，毫秒字段全被当成 0 —— 表现为"后端记录 N 条，更新本地 0 条"，数字照样补不上。
   现在数字与字符串两种写法都认，键名也做了别名与大小写兼容
   （`totalOnlineMillis`/`onlineMillis`、`totalAfkMillis`/`afkMillis`、`currentOnlineSince`/`onlineSince`）；
   顶层没有累计时还会退回按 `subServers` 明细求和。
2.调整：列表接口的路径回退从"仅 403/404"放宽到"任意非 2xx"（管理端在部分部署上返回 500），
   并记住上次成功的路径，之后直接走它，不再每次都白撞一次错误。
3.调整：对齐成功但没有任何字段被采纳时，回执里会带上一条**记录样例**（截断），
   直接在游戏里就能看出后端实际返回的字段名。

[Beta_1_8_2 -> Beta_1_8_3] 2026.10.19 17:30:00
1.修复了本地时长比后端多出一截（例如本地 1小时53分钟 / 后端 1h31m）：后端玩家列表返回的累计是
   `totalOnlineMillisAt(now)` —— **已经含当前未结算的这次在线**（AFK 同理，子服明细也是 `onlineAt(now)`），
   而合并时把它当成"已结算值"存进本地，本地显示又加上自己那段开区间，等于把当前这次在线算了两遍。
   现在采用前先按各自的 `currentOnlineSince` / `currentAfkSince` 把开区间减掉，还原成真正的已结算值。
2.新增：`/yudreammc playtime [玩家]` 除本地数字外，还会异步打印**后端侧的数字**做对照
   （口径与后端界面一致：含当前这次在线），眼见为实，不用两边来回对表。
