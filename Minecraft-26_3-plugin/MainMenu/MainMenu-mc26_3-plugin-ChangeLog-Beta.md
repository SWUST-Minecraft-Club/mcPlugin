# MainMenu ChangeLog（测试版）

版本命名与产物见 `./docs/dev/版本与产物规范.md`。
格式：`[新版本] 时间` 或 `[上一版本 -> 新版本] 时间`，下面列本次改动（新增 / 修复 / 调整）。

---

[Beta_0_1_0] 2026.10.17 12:54:26
1.新增主菜单界面：6×9 布局、功能区 21 格/页、翻页箭头
2.新增三种打开方式：ESC 菜单里的「主菜单」按钮、`/cd` 命令、手持时钟右键
3.新增功能插件 API（`com.example.mainmenu.api`）：物品 / 悬停文本 / 点击是否有效 / 点击行为 / 自定义位置
4.新增位置冲突处理：与固定功能位或其它插件冲突时自动归到功能区，并在悬停文本末尾追加提示
5.新增功能区排序与分页：按注册顺序填充，每页 21 个
6.新增 `/cd reload`、`/cd debug`（布局预览、功能位置、ESC 按钮状态、配置自检）

[Beta_0_1_0 -> Beta_0_2_0] 2026.10.17 13:30:10

[Beta_1_0_2 -> Beta_1_1_0] 2026.10.19 13:50:00
1.新增：功能项支持按查看者渲染 —— `MenuFeature` 增加 `icon(viewer)` / `description(viewer)` 默认方法

   主菜单与功能管理界面渲染时都会把"正在看菜单的玩家"传进去，功能插件因此能做到
   「每个玩家看到自己的数据」（首个用例：显示查看者自己的在线时长）

   悬停文本换成查看者上下文后仍会追加插件名 / id / 状态行
3.配套：《功能插件接入规范》新增「按查看者渲染」一节（写法、时机与注意事项）

[Beta_1_1_0 -> Beta_1_2_0] 2026.10.20 10:30:00
1.新增：`MainMenuApi.open(player)` / `openOrNull(player)` —— 功能插件在自己的界面里做「返回上一级」时，
   可以直接替玩家重新打开主菜单（此前只能靠命令，插件拿不到打开入口）；MainMenu 启动时把
   `MenuService.open(player)` 注册进去，未加载时 `open` 抛异常、`openOrNull` 返回 false
2.配套：《功能插件接入规范》补「打开主菜单」的用法说明

[Beta_1_2_0 -> Beta_1_2_1] 2026.10.20 15:00:00
1.调整：不再给功能物品的悬停文本追加「点击使用 / 点击无效」提示 —— 这两行只是给开发者看的说明，
   玩家侧不需要；`menu.feature.clickable-hint` / `not-clickable-hint` 两个配置项一并移除
   （旧配置文件里留着也不再生效），位置冲突提示 `conflict-hint` 保持不变

[Beta_1_2_1 -> Beta_1_3_0] 2026.10.22 23:45:00
1.新增：适配 Folia 26.3 服务端 —— `paper-plugin.yml` 声明 `folia-supported: true`，
   编译依赖由 Paper API 改为 Folia API（`dev.folia:folia-api`），测试服 `runServer` 改为启动 Folia
2.调整：菜单打开、翻页、周期重绘全部改走 Folia 实体调度器（`player.getScheduler()`），
   背包创建 / 填充 / 打开 / 重绘只在该玩家所属区域线程执行；ESC dialog 回调与 `/cd` 统一延迟 1 tick 开界面
3.修复：菜单刷新任务表、打开冷却表、时钟右键冷却表改用并发容器；功能管理状态读写加同步，
   避免不同区域线程同时渲染 / 管理时互相踩踏

[Beta_1_3_0 -> Beta_1_4_0] 2026.10.23 14:32:00
1.新增：管理页第 1 行第 1 格「添加功能占位符」按钮 —— 在功能区末尾添加一个占位符，
   管理页左栏用红色染色玻璃板显示；主菜单渲染时跳过占位符（保留空位），玩家侧不可见
2.新增：占位符属性页只提供「排序值」和「删除该功能插件占位符」两个操作；
   占位符参与功能区排序与分页，排序值写入 `features.yml` 的 `features.<id>.order`
3.配套：占位符列表持久化在 `features.yml` 的 `placeholders` 段，重启后恢复；
   功能插件 `unregister` 不会误删占位符；`/cd debug` 将占位符标记为「占位符」
