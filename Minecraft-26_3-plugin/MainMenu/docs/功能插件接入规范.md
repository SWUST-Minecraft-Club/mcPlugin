# 主菜单功能插件接入规范

本规范写给**以 MainMenu 为依赖的后续插件**：把功能挂到主菜单上，由玩家通过 ESC 菜单按钮 / `/cd` / 手持时钟右键打开。

主菜单本体由 MainMenu 插件负责，功能插件只提供四件事：

| 要素 | 对应 API | 说明 |
| --- | --- | --- |
| 用什么物品显示 | `icon(...)` | 物品（材质/附魔/自定义模型都保留），也可以直接用 `ItemStack` |
| 鼠标悬停显示什么文本 | `name(...)` / `line(...)` / `lines(...)` | MiniMessage 文本，多行 |
| 点击是否有效 | `clickable(true/false)` | 不设置默认 `false`（纯展示） |
| 点击后做什么 | `onClick((player, clickType) -> ...)` | 设置后自动视为可点击 |
| 显示位置（可选） | `preferredSlot(int)` | 0~53，且必须是**功能区以外**的格子；不设置则进功能区 |
| 功能区排序（可选） | `order(int)` | 越小越靠前，默认 `0`（按注册顺序） |

---

## 1. 依赖与加载顺序

### 1.1 `paper-plugin.yml`

```yaml
name: Shop
version: '${version}'
main: com.example.shop.ShopPlugin
api-version: '26.3'

# 关键：声明依赖 MainMenu，保证它先加载，才能在 onEnable 里注册功能
dependencies:
  server:
    MainMenu:
      load: BEFORE
      required: true
```

`required: true` 表示主菜单缺失时你的插件不会加载（推荐，避免注册失败）。
若希望主菜单缺失时仍能运行，用 `required: false`，并在注册前判断 `MainMenuApi.isAvailable()`。

### 1.2 `build.gradle`

同一个仓库内的插件直接依赖工程即可（只用于编译，运行期由服务端提供）：

```groovy
version = '0.1.0'

dependencies {
    compileOnly project(':MainMenu')
}
```

不同仓库时把 MainMenu 的 jar 放进 `libs/` 或发布到私有仓库，同样用 `compileOnly`。

## 2. 注册一个功能

```java
package com.example.shop;

import com.example.mainmenu.api.MainMenuApi;
import com.example.mainmenu.api.MenuFeature;
import net.kyori.adventure.text.Component;
import org.bukkit.Material;
import org.bukkit.entity.Player;
import org.bukkit.plugin.java.JavaPlugin;

public final class ShopPlugin extends JavaPlugin {

    @Override
    public void onEnable() {
        MainMenuApi.registry().register(
                MenuFeature.builder("shop:main")          // id：建议 "<插件名>:<功能名>"
                        .owner(getPluginMeta().getName())  // 可选，默认取 id 里 : 之前的部分
                        .icon(Material.EMERALD)            // 用什么物品显示
                        .name("<green>商店</green>")        // 物品显示名
                        .line("<gray>点击打开商店</gray>")   // 悬停文本（可多行）
                        .onClick((player, clickType) -> openShop(player))  // 点击做什么
                        .build());
    }

    @Override
    public void onDisable() {
        // 插件卸载/重载时把功能摘掉，避免留下悬空引用
        MainMenuApi.registryOrNull().unregister("shop:main");
    }

    private void openShop(final Player player) {
        player.sendMessage(Component.text("打开商店"));
    }
}
```

### 动态文本

`icon()` 与 `description()` 在**每次渲染时**都会被调用（菜单打开期间固定格每秒刷新一次），所以余额、冷却这类会变的内容可以直接实时算：

```java
MenuFeature.builder("shop:balance")
        .icon(Material.GOLD_INGOT)
        .name("<gold>我的余额</gold>")
        .line("<gray>当前：<white>" + balance(player) + "</white></gray>")  // 注意：这里拿不到 player
        .build();
```

> 功能项的文本在注册时确定，拿不到“正在看菜单的玩家”。需要按玩家变化的文本，请在 `icon()` 实现里读取缓存（例如在 `PlayerJoinEvent` 时预取），或让功能在点击后自行刷新（`player.sendMessage(...)`）。

## 3. 位置规则

主菜单是 6×9（54 格），布局如下（`slot` 为 0 基编号）：

```
第1行   [ 0]玻璃板 [ 1]时间* [ 2]玻璃板 [ 3]玻璃板 [ 4]玻璃板 [ 5]玻璃板 [ 6]玻璃板 [ 7]玻璃板 [ 8]玻璃板
第2行   [ 9]玻璃板 [10]玻璃板 …… （第 2 行整行玻璃板）
第3行   [18]玻璃板 [19]功能区 [20]功能区 [21]功能区 [22]功能区 [23]功能区 [24]功能区 [25]功能区 [26]玻璃板
第4行   [27]上一页 [28]功能区 [29]功能区 [30]功能区 [31]功能区 [32]功能区 [33]功能区 [34]功能区 [35]下一页
第5行   [36]玻璃板 [37]功能区 [38]功能区 [39]功能区 [40]功能区 [41]功能区 [42]功能区 [43]功能区 [44]玻璃板
第6行   [45]玻璃板 …… （第 6 行整行玻璃板）
```

- **固定功能位**（`27` 上一页、`35` 下一页）：任何插件都不能占用。
- **非固定功能位**（其余所有非功能区格子，默认是白色染色玻璃板）：功能插件可以用 `preferredSlot` 占用。
- **功能区**：第 3~5 行、第 2~8 列，共 **21 格**，由主菜单按注册顺序填充，可翻页。

> 第 1 行第 2 格（`slot 1`）常规留给"当前时间"，由 RealTime 插件用 `preferredSlot(1)` 占用（图中 `时间*`）。
> 位置先到先得，别的插件技术上也能用这一格，只是别去抢它。

> 第 6 行第 5 格（`slot 49`）是管理入口，属于固定功能位，功能插件不能占用。

功能插件的位置、排序、显示 / 隐藏都可以在游戏里由管理员调整（主菜单第 6 行第 5 格进入），
调整结果保存在 `plugins/MainMenu/features.yml`。所以插件只需声明"默认值"，后续微调交给管理员。

### 3.1 不设置位置

按注册顺序排进功能区，第 1 页放满 21 个后自动进第 2 页，依此类推。

### 3.2 自定义位置

```java
.preferredSlot(0)   // 第 1 行第 1 格（非固定功能位，允许）
.preferredSlot(19)  // 功能区格子 —— 视为“未设置位置”，按顺序进功能区
.preferredSlot(27)  // 固定功能位（上一页）—— 冲突，见下
```

### 3.3 冲突处理

以下情况判定为**位置冲突**：

1. 与固定功能位冲突（`1` / `4` / `27` / `35`）；
2. 该格子已被其它插件的自定义位置占用（先注册者优先）。

冲突时不会报错，也不会挤掉别人，而是：**该功能自动排进功能区**，并在它的悬停文本最后追加一行：

```
该功能插件位置不可用，已自动归到功能区
```

这行文案可在 MainMenu 的 `config.yml` → `menu.feature.conflict-hint` 修改。
`preferredSlot` 落在功能区或超出 0~53 时不算冲突，只当作“没有自定义位置”。

### 3.4 分页

- 每页功能区 21 格，页数 = `ceil(功能区功能数 / 21)`，至少 1 页。
- 自定义位置的功能**不在功能区**，每页都会显示。
- 翻页只用主菜单自带的箭头（第 4 行第 1 / 第 9 格），功能插件不需要关心分页。

### 3.5 排序

功能区先按 `order(int)` 升序排列，`order` 相同的再按注册顺序（稳定排序）。默认 `order = 0`。

注意：**跨插件的“注册顺序”等于服务端的插件加载顺序，由服务端决定，不一定是字母序**（实测 Paper 26.3 按插件名逆序加载）。所以：

- 想让自己的功能稳定排在某个位置，用 `order(...)`（例如 `order(10)`、`order(20)`，留出间隔方便以后插入）；
- 想固定占某一格，用 `preferredSlot(...)`；
- 同一个插件内注册多个功能时，它们之间的先后就是代码里的注册顺序。

## 4. 交互约定

- 菜单里的物品**一律不可移动**（含 shift 点击、拖拽、数字键交换），主菜单会取消这些操作。
- 只有 `clickable(true)` 的功能会收到点击回调，回调参数是 `(Player, ClickType)`，可据此区分左键/右键/shift。
- 点击回调在**主线程**执行，可以安全地操作世界、打开其它 GUI、发消息。
- 回调里抛出的异常会被主菜单捕获并记入日志，不会影响其它功能。

## 5. 自查

主菜单提供了 `/cd debug`（权限 `mainmenu.reload`），会输出：

- 内置数据包与 ESC 菜单按钮（`pause_screen_additions` 标签）状态；
- 每个功能最终落在哪一格、第几页、是否因冲突被改排；
- 6 行 × 9 列的布局预览（`[槽位]名称`，带 `*` 的是自定义位置占用）；
- 配置文本自检。

注册后执行一次 `/cd debug`，确认自己的功能出现在预期格子上即可。
